Action Control 原生相机复用进度，版本 0.1.8，已部署，2026-09-18。

**当前实现是原生服务的只读观察、采集状态语义修正和快捷接管保护。原生拍照、录像控制及网页原生预览还没有实现，不能用“服务运行”代替这些能力。** 用户已允许断开手机后继续开发；以下明确区分不依赖 Mimo 的工作，以及必须等 Mimo 重新连接才能验证的事项。

| 已实现内容 | 具体行为 |
| --- | --- |
| 原生服务状态 API | `GET /api/native_camera_status` 只执行带 3 秒超时的 `systemctl show`，读取原生相机、媒体、双屏界面和 Mimo 通信服务的状态及主进程 PID |
| 独立诊断命令 | `action-control native-status` 输出同一份 JSON；不创建应用配置、不启动网页服务、不发送相机私有命令 |
| 状态语义分离 | 原有 `GET /api/camera_status` 增加 `source=action-control`、`scope=independent_capture`；其分辨率、帧率和运行状态仍只属于独立采集 |
| 默认页面 | 首先显示原生服务状态；原生录像与预览明确显示“未接入”，独立采集收进默认折叠的高级入口 |
| 接管保护 | `camera_start` 和 `dji_kill_all` 必须同时带 `confirm=true` 和 `takeover_native=true`；仅有旧确认字段时返回 409，在配置写入、监听端口、停止服务及屏幕操作前结束 |
| 原有独立采集 | 保留现有功能及启动确认，主动接管时明确说明会影响原生相机、屏幕及 Mimo；停止自身采集仍可使用原来的停止接口 |
| 网络共用 | 延续 0.1.7 的原生网络策略，由原生网络服务管理无线；本次没有增加一套热点、DHCP 或网络状态机 |

原生状态接口始终返回 `source=systemd`。`recording`、`previewing` 在此版本为 JSON `null`，`control_available`、`preview_available` 为 `false`。没有把服务存在、编码线程存在或预览流量猜测成精确拍摄状态。

`service_state` 的含义如下：

| 值 | 含义 |
| --- | --- |
| `running` | 本次读取的五个原生服务均为 loaded / active / running，且具有非零主进程 PID |
| `stopped` | 五个服务均为 inactive / dead，且 PID 为 0 |
| `degraded` | 状态完整，但部分服务停止或失败 |
| `transitioning` | 状态完整，至少一个服务正在启动或停止 |
| `unknown` | 查询失败、超时、输出不完整或矛盾；无法给出完整判断 |
| `unavailable` | 非目标相机或本地文件模式，不访问硬件 |

`services` 中保留各个单元的原始 `load_state`、`active_state`、`sub_state`、`main_pid`，并给出逐项的观察状态；`observed_at` 是观察时间。Mimo 通信服务运行只表示进程可用，不表示手机在线。这个 API 不查询 DUSS/Binder 相机状态，也不触发预览订阅。

接管保护针对两条会批量停止原生服务的快捷 API，使用显式请求字段表达本次操作的意图，不新增持久化相机模式。已有 root 命令执行和进程管理仍是独立的管理员功能；本次保护不是系统权限隔离。网络设置不因打开或关闭高级采集面板而改变。

原生复用的下一步应优先研究相机本地客户端库，减少重复实现 Mimo 的无线协议。已复制的 `libdcam_camera_service_client.so` 中发现以下 C 导出入口，并离线检查了部分函数体：

| 入口 | 当前证据 | 后续所需工作 |
| --- | --- | --- |
| `camera_manager_create` / `camera_manager_destroy` | 创建、释放相机管理客户端；可见 Binder 初始化和独立客户端名 | 核对创建参数结构、客户端注册及销毁生命周期 |
| `camera_manager_connect_camera` | 获取相机客户端对象 | 确认连接/释放不会抢占原生界面或改变相机工作模式 |
| `camera_manager_get_workmode` | 读取管理器工作模式的客户端调用 | 核对返回码、枚举和断连行为 |
| `camera_get_record_state` / `camera_get_capture_state` | 导出符号存在；录像 getter 通过设备句柄进入原生 Binder 代理，输出参数为整数状态 | 完成句柄生命周期、枚举、超时及错误行为的验证 |

这些本地入口不以手机连接为前提。当前还没有完整的 ABI 和生命周期证明，因此没有通过猜测结构体或函数签名在相机上调用它们，也没有对外提供拍摄按钮。它们属于继续进行的本地协议研究，不能记为“必须等待 Mimo 才能开始”的项目。

网页原生预览最终需要取得原生编码数据，再选择浏览器支持的传输封装；目前不能承诺已经有 RTSP 地址、已经能多客户端订阅，或任何协商格式都能免转码。原生录像状态适配完成后，也应使用原生结果更新页面，不另行维护拍摄状态机。
